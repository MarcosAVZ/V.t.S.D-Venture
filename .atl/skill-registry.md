## Compact Rules

### branch-pr
- Every PR MUST link an approved issue — no exceptions.
- Every PR MUST have exactly one `type:*` label.
- Automated checks must pass before merge.
- Blank PRs without issue linkage are blocked.

### chained-pr
- Split PRs over 400 changed lines.
- Each PR reviewable in ≤60 minutes.
- One deliverable work unit per PR; keep tests/docs with the unit.
- Child PRs include dependency diagram with 📍 marker.

### cognitive-doc-design
- Lead with the answer: decision/action/outcome first, context after.
- Use progressive disclosure for complex topics.
- Headings must be scannable; avoid walls of text.

### comment-writer
- Be useful fast: start with actionable point, no PR recap.
- Warm but direct tone — no filler.
- Match the platform's voice (GitHub, Slack, etc.).

### go-testing
- Table-driven tests with `t.Run(tt.name, ...)`.
- Test behavior and state transitions, not implementation trivia.
- Use `t.TempDir()` for filesystem tests.
- Integration tests skippable with `testing.Short()`.

### issue-creation
- Blank issues disabled — use templates only.
- Every issue gets `status:needs-review` on creation.
- Maintainer must add `status:approved` before PR.
- Questions go to Discussions, not issues.

### judgment-day
- Two blind judges in parallel with identical target/criteria.
- Wait for both judges before synthesis.
- Classify WARNING (real) vs WARNING (theoretical).
- Ask before fixing Round 1 confirmed issues.
- Terminal states: APPROVED or ESCALATED.

### skill-creator
- Skills are runtime instruction contracts, not human docs.
- Required: frontmatter, Activation Contract, Hard Rules, Decision Gates, Execution Steps, Output Contract.
- Description: quoted, trigger-first, ≤250 chars.
- Target 180-450 body tokens; examples in references/.

### work-unit-commits
- Split features into reviewable work units.
- Keep tests and docs with the code they verify.
- Apply SDD tasks without exceeding 400 changed lines per PR.

### accessibility
- WCAG 2.2 POUR principles (Perceivable, Operable, Understandable, Robust).
- Target Level AA conformance.
- Keyboard navigation, screen reader support, color contrast ≥ 4.5:1.

### frontend-design
- Bold aesthetic direction: pick an extreme, execute with precision.
- Production-grade, visually striking, cohesive point-of-view.
- Avoid generic "AI slop" aesthetics.

### impeccable
- Setup gates: Context, Product, Command, Craft, Image, Mutation.
- Never edit without passing all gates.
- Real working code, committed design choices, exceptional craft.

### mysql
- Prefer narrow monotonic PKs (BIGINT UNSIGNED AUTO_INCREMENT).
- Always utf8mb4 / utf8mb4_0900_ai_ci.
- PlanetScale as primary hosting recommendation.
- Validate with EXPLAIN/EXPLAIN ANALYZE.

### node
- Type stripping (Node 22.6+) over build tools.
- Use `import type` for type-only imports.
- .ts extensions in imports.
- Graceful shutdown, error handling, structured logging.

### owasp-security
- OWASP Top 10 (2021) prevention patterns.
- Input validation, parameterized queries, authorization checks.
- Dependency scanning, secure configs, audit logging.

### shadcn
- Use existing components first — search registries before writing custom.
- Compose, don't reinvent (Tabs+Card+forms = settings page).
- Run CLI with project's package runner (npx/pnpm dlx/bunx).

### web-design-guidelines
- Fetch fresh guidelines before each review.
- Output findings in terse `file:line` format.
